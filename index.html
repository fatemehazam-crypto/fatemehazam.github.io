OCII · Full-stack platform

Smart-City Real-Time Monitoring Platform

Live telemetry from a distributed sensor network, streamed to a browser dashboard.

I designed and built a full-stack, real-time monitoring platform for smart-city cybersecurity research at OCII. It ingests live data from about seven ESP32 sensor nodes across several buildings, covering four RF bands (Wi-Fi, 433 MHz, GPS L1/L5 and LoRaWAN), and streams it to a browser dashboard over an event-driven MQTT and Socket.io architecture. It detects and classifies RF disruption in real time and shows live telemetry from drone missions alongside the sensor network. I also write and flash the C++ firmware on the sensor nodes.

  • React front end with live sensor dashboards, RF disruption analysis, and drone flight paths drawn on an HTML5 canvas.
  • Node.js backend with MQTT ingestion, metric normalization across devices that each report differently, Socket.io broadcast, a REST API, and SQLite storage.
  • A drone-tracking view that follows swarm delivery missions and raises alerts.
  • Drone telemetry integration with ROS 2 output and automated MCAP flight recording, plus an MJPEG video proxy and PCM audio over WebSocket.

ThunderPlains 2026: the live demo the audience tried to break

My 50-minute talk, When Every Device Speaks a Different Language: Building Resilient Event-Driven Systems, was built on this platform. Audience phones joined the testbed's MQTT bus live through a QR code and a relay hosted on Render. Developers in the room wrote scripts to flood it with junk data. It stayed up.

OCII / OCAST · Published research

Micro-UAV Command-Stack Security & Swarm Hijack Detection

Presented at IEEE CARS 2026, now extending to multi-drone delivery swarms.

As drone operations move into cities and multi-drone missions, a compromised command channel becomes a real risk. This work is part of an OCAST-supported initiative led by OCII to position Tulsa as a regional hub for unmanned aerial systems and smart-city technology. On a Crazyflie testbed we characterized a class of command-authority vulnerabilities in micro-UAV command stacks, then built a detector that flags hijacks from flight telemetry alone. The work was accepted and presented as Authority Contention in Micro-UAV Command Stacks at IEEE CARS 2026.

0.906F1 score, Random Forest on telemetry
1.18%false-positive rate
3.55%false-positive rate, rule-based baseline
Delivery missions and trajectory planning

Drones fly grid-aligned delivery routes in parallel, following "streets" through the testbed, descending at each drop-off and returning home. The same routes can be flown waypoint by waypoint, or as one smooth 7th-order polynomial trajectory that each drone flies onboard, rounding corners and drop-offs without stopping. That cuts a mission from about 2 min 45 s to about 1 min 15 s.

Battery monitoring and flight-time estimation

A small library on the drone's power telemetry decides before every leg whether to keep flying, return to base, or land, and refuses to take off without battery data. It estimates remaining flight time from a voltage lookup table built from a recorded discharge flight.

Rule-based flight monitor (baseline)

Fixed-threshold rules flag drones that leave their planned route or stop sending telemetry, escalate gaps from warning to critical, and record every outage. A live map shows each drone's route, track and status next to an event log. Simple, transparent rules like these make a baseline to compare learned detectors against.

ML hijack detector

A Random Forest classifier trained on flight telemetry separates hijacked flights from normal ones. It reached an F1 score of 0.906, and cut false positives to 1.18% against 3.55% for the rule-based baseline.

Next phase: multi-drone swarm generalization

The next phase extends detection to multi-drone delivery missions and tests generalization across drones, routes and drone pairings the model has never seen, not just held-out samples. Early trial data reshaped the design: a hijack attempt is detectable from the radio link seconds before the flight path changes. That led to a two-signal architecture, an early link-quality signal confirmed by a trajectory-residual signal once the flight starts to deviate.

  • Data collection. Python mission control, MQTT telemetry, and mission profiles generated from a city layout config.
  • ROS 2 and telemetry. A multi-drone bridge, MCAP flight recording, and Foxglove for visualization and analysis.
  • Applied ML. scikit-learn, XGBoost and PyTorch with CUDA, Optuna for tuning and MLflow for tracking; Random Forest, XGBoost and sequence models compared against the published baseline with leave-one-drone-out and leave-one-mission-out validation.
  • Real-time detection. A Rust node running the model through ONNX Runtime, publishing alerts back onto the ROS 2 graph.

In progress Active data collection and pipeline development, building on the published CARS 2026 results.

Scope and ethics. All experiments ran in a controlled lab, on hardware we own, with defensive intent. No third-party systems were targeted. Attack tooling is not published; public material covers the vulnerability class at the level the paper describes it, the detector, and the testbed software.

OCII · Educational game + analytics

Catch the Phish: Before the Phish Catches You!

A Godot arcade game that teaches phishing detection, with a real-time analytics platform behind it.

Beyond research, I build software that ships and gets used. In Catch the Phish, players catch phishing emails on fishing hooks and let the legitimate ones swim past, while Bitey the fish tries to trip them up. Points come from catching phish; missing one or grabbing a real email costs you. The game gets harder as players improve, with more convincing phishing patterns, spoofed domains and less time to decide.

It's used in Oklahoma middle and high school classrooms as part of OCII's cybersecurity curriculum, was showcased at the 58th Oklahoma Summit and the OKC Innovation event, and runs on arcade cabinets I built with a Raspberry Pi at four Vast Bank branches in Tulsa. I own the project end to end.

Play on itch.io

Game design and implementation

Built in Godot 4 for both arcade cabinets and the browser. Difficulty adjusts to each player's accuracy and reaction time, and the phishing patterns get more sophisticated as they progress.

  • Godot 4.x engine, exported to desktop and HTML5.
  • Dynamic difficulty adjustment.
  • A phishing-pattern system with increasingly sophisticated examples, domain-spoofing cues and timing pressure.
  • Scoring with rewards for caught phish and penalties for misses and false catches.
  • Arcade cabinets built around a Raspberry Pi with a speaker, encoder and monitor.
Real-time analytics architecture

The HTML5 build talks directly to an analytics service on a self-hosted Ubuntu server. Every gameplay event (choices, mistakes, response times, difficulty changes, sessions) is logged in real time and can be explored through a dashboard.

  1. Godot gameruns in the browser as an HTML5 export
  2. JavaScript bridgesends JSON events over HTTP
  3. Express APIvalidates and stores each event
  4. MongoDBindexed event collections for aggregation
  5. Dashboardaccuracy, response time, phishing type, level progression

The dashboard is vanilla HTML and JavaScript over a REST API, with real-time charts that support classroom monitoring and long-term studies.

Personal project · AI / LLM security

Reel Smart

A local-LLM pipeline that writes phishing-awareness training content, and is hardened against attacks on itself.

Reel Smart generates, scores and evolves phishing-awareness training messages with local models. It started as an agent producing fresh phishing examples for Catch the Phish, and grew into a pipeline in its own right. Nothing leaves the system until a person has reviewed and approved it.

  1. Generatelocal LLM via Ollama
  2. Scoredetector tags the clues
  3. Evolveimprove on the best-scoring drafts
  4. Reviewhuman approval gate
  5. Exportto training content
  • The detector, not the model, writes the clue tags. It is calibrated against human-labeled data to about 82% agreement.
  • A red-team suite mapped to the OWASP Top 10 for LLM Applications and the OWASP Agentic Top 10. Prompt injection, poisoned-feed, secret-leakage and misuse cases are all blocked with defenses on.
  • A live threat-intelligence feed from the FBI's IC3, behind layered defenses: a source allowlist, headline sanitization, and passing the model labels rather than raw text.
